GO-2026-6859 — reachable net/http server crash (MaxBytesReader header race)

go.mod:3 (go 1.27.3) · net/http@go1.27.3 → fixed in go1.27.4

govulncheck exit 3: “Your code is affected by 1 vulnerability from the Go standard library.” HTTP/1 servers can be crashed by a race involving MaxBytesReader and header handling. This module ships a long-lived HTTP server (appkit svc.Run in cmd/pbx-lens/serve.go, plus the Telnyx ingester client and OIDC login) — the scan surfaced 49 symbol-level call traces into net/http, so reachability is not in doubt. Classified Critical per the scan rubric (security vulnerability); nuance for triage: it is DoS-class (crash, no RCE/data loss) and the service is LAN-facing per the NixOS deploy module, with the fix already published.

Fix Bump the module's Go level to 1.27.4 (go 1.27.4 in go.mod — or add a toolchain directive), align the devShell's pinned toolchain (GOTOOLCHAIN=local), rebuild, and re-run govulncheck ./... expecting exit 0. The GOEXPERIMENT=jsonv2 pin is unaffected. Everything else in this fix is mechanical — no code changes required.

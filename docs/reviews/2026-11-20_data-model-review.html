01Problem Catalog

Ten findings, ordered by impact. Each is graded for severity and systemicity, and each fix is classified by its blast radius: hash-safe (no change to any hash pre-image), schema bump (moves ContentHash — needs ObservationSchemaVersion 3 plus one backfill), or event-frozen (would break append-only history — forbidden).

High · systemic

PC-1 · The read model is a hand-maintained mirror, not a composition

internal/calls/projection.go:20–86 · internal/cli/enrich.go:196–201 · internal/cli/refresh.go:179–191

CallView re-declares all 14 Observation fields and all 3 Enrichment fields, flattened by hand. ViewFrom copies them field-by-field; CallView.Observation() copies them back; cli.enrichmentOf copies the enrichment out a third time. Adding one Observation field means touching four places, and the codebase built tooling to police that drift: the round-trip invariant tests, the additive-only refresh detector, and the schema-version bump procedure all exist largely because a mirror can silently lose a field. The enrich pass even depends on the mirror's exactness for correctness — dispatchEnrich addresses the command through view.Observation(), so a missed field would emit an event carrying a wrong snapshot. 

// today: three hand-synced projections of one shape
func ViewFrom(obs Observation, enr Enrichment) CallView { // 17 assignments }
func (v CallView) Observation() Observation { // 14 assignments back }
func enrichmentOf(view CallView) Enrichment { // 3 more }
Fix: embed, don't mirror hash-safe type CallView struct { Observation; Enrichment; ContentHash string } — Go's embedding promotes fields, so the stored JSON is byte-identical (tags already match exactly), metaengine's top-level column addressing (started_at, direction, from_number…) keeps working, and ViewFrom / Observation() / enrichmentOf collapse into one-line constructors. The index is disposable: one cli.ResetReadModel rebuild after landing. ContentHash itself is untouched — it hashes Observation, not the view.
Medium · systemic

PC-2 · The stream lifecycle is parallel booleans, not a state

internal/calls/decider.go:12–20, 84–216

CallState encodes a three-state lifecycle (unobserved → observed → retired) as two independent booleans plus free-form hashes. The domain's hardest invariant — a retired stream accepts no appends — is enforced by three separate runtime guards (call.corrected.after_retired, call.enrich.after_retired, the retire no-op), each of which must remember to check. Invalid intermediates (Observed=false, Retired=true) are representable. One implicit assumption is load-bearing: Apply on call.observed does not reset EnrichHash, which is only safe because Observed is structurally always the first event — nothing in the type says so.

Fix: closed union over fold state hash-safe Model the states as a sum type (see Go Data Model below): the Retired variant simply has no slot for a new snapshot or enrichment, so the guards become a type switch and the illegal append stops compiling. Fold state is never persisted — events are untouched, history replays identically.
Medium · systemic

PC-3 · Stream identity never got its own type

domain.go:105–114 · representative.go:43 · queries.go:622 · commands.go:88 · retention.go:171 · cli/ingest.go:70 · cli/telnyx.go:49–53

Observation.StreamID() builds identity by string concatenation inside a method of the observation itself, so every caller that holds only a kind and a native id constructs a zombie observation to compute a stream id — the representative join, the detail-page join, and NewRetireCommand all do it. Meanwhile five sites re-derive the kind:id display form by hand (streamLabel ×2, stallContext, dedupeKey with a different separator), and EnrichmentSeed.StreamKey is a bare string whose zero value is silently dropped by SeedsFor.

Fix: a branded StreamKey with one constructor hash-safe calls.StreamKeyOf(kind, nativeID) (StreamKey, error) owning build/parse/render; Observation.StreamID and the zombie call sites delegate to it; EnrichmentSeed carries the branded type; labels derive from its String(). Pure code motion — no payload, no hash, no event changes.
Medium · localized

PC-4 · Enrichment's one structural invariant is unvalidated

domain.go:237–267 · decider.go:146–183

An Enrichment with CostMicros > 0 and an empty CostCurrency compiles, validates nowhere, and dispatches: NewEnrichCommand validates the observation but not the enrichment, and telnyx.CostOf bounds the parsed value without pairing it. The dashboard's mixed-currency refusal would later sum it wrongly rather than refuse early. The pairing — micros are meaningless without their unit — is the type's only real invariant and nothing checks it.

Fix: validate at the command boundary hash-safe Enrichment.Validate() (micros > 0 ⇔ currency non-empty; currency is uppercase ISO-4217 when present), called from NewEnrichCommand and the decider's Enrich — same pattern as Observation.Validate at NewRecordCommand. The hash pre-image is value-driven, so validation changes nothing until a bad value appears.
Medium · localized

PC-5 · Two public types for one retention window

cli/ingest.go:81–108 · retention/retention.go:39–63

cli.AgeGate{MaxAge} and retention.Policy{MaxAge} are the same type: the same field, the same zero-keeps-everything contract, and AgeGate.Apply literally constructs a Policy to delegate to Admits. The ingest half and the purge half of one doctrine (DOMAIN_LANGUAGE: age gate) are two names for one concept, so the "shared by serve poller and one-shot commands" guarantee rests on convention, not on the type.

Fix: keep Policy, delete AgeGate hash-safe The CLI already imports retention; GateIngest takes a retention.Policy and calls Admits directly. One type, one contract, one place to change the boundary semantics (inclusive cutoff).
Low · localized

PC-6 · Hash digests are interchangeable bare strings

decider.go:12–20 · projection.go:38

CallState.ContentHash, CallState.EnrichHash, and CallView.ContentHash are all plain string, so comparing an enrichment hash against a content hash compiles. Equality of digests is identity in this domain — the two digest spaces should not mix silently.

Fix: two alias brands hash-safe type ContentDigest string and type EnrichDigest string over the state and view fields. Aliases keep JSON, sqlite storage, and the hash computation itself byte-identical.
Low · localized

PC-7 · The agent transcript line decodes as a fat union

internal/ingest/agent/agent.go:37–45

line is one struct for all three JSONL variants (start/turn/end): the discriminator is a string compared in a switch, and every variant's fields are visible to every other (a turn carrying a uuid is representable and ignored). Tolerant wire decoding is the right call here — the writer is a sibling Python module — so this is recorded as an accepted cost, with the observation that normalizeTurn already closes the vocabulary that matters (caller/agent → user/assistant).

Verdict: accept, with a note A tagged-union decode (three structs behind a small interface) would type the variants, but the file format is owned by the same operator and the fat struct is 9 lines. Revisit only if the writer grows discriminators.
Low · localized

PC-8 · Direction has a hidden third value

cdr/cdr.go:229–257 · domain.go:80–89

The type declares two values and Valid() denies everything else, yet the CDR pipeline speaks a third: Direction("") as "no dialplan verdict" flows through classifyExtras and parseDeclaredDirection before the heuristic derivation resolves it. It is never persisted (direction() always falls through to a verdict), so this is a pipeline-internal tri-state the type does not name — the classic enum-with-undocumented-sentinel.

Fix: name the intermediate hash-safe type declaredDirection struct{ v Direction; ok bool } (or (Direction, bool) returns, matching parseDeclaredDirection's existing shape) inside the cdr package. Persisted Direction stays exactly two-valued.
Low · localized

PC-9 · Rejection lists flatten error class to strings

cli/ingest.go:15–27 · cli/enrich.go:14–29 · retention/retention.go:68–72

IngestStats.Rejected, EnrichStats.Rejected, and retention.Report.Rejections are []string. For operator display that is the right shape — but terminal refusals (call.enrich.after_retired: never retried, by design) and retriable ones (a lagging projection counting Missing) are indistinguishable without string matching, and the poller surfaces these counters to ops.

Fix: classify at append time hash-safe A tiny Rejection{Stream, Err error, Terminal bool} (or errorfamily classification) behind the same String() rendering keeps the operator output identical while making the poller's retry math honest.
Low · cosmetic

PC-10 · nil/empty inconsistency in the over-age scan

retention/retention.go:79–109

OldViews returns nil, nil when the policy is unbounded but a non-nil empty slice otherwise; Retire iterates, so behavior is identical. The mappers, by contrast, build non-nil empty slices for stable JSON. Cheap to align, zero urgency.

02The Vision

What the model looks like when the three structural findings are paid down — judged against this project's scale, not an enterprise checklist:

+
One shape, stated once Observation and Enrichment are each declared exactly once; the read model composes them by embedding, so a new field lands in the view the day it lands in the domain — no mirror to update, no drift detector needed for the mirror class.
+
Lifecycle invariants that stop compiling when broken "A retired stream accepts no appends" is carried by the state's shape (the Retired variant has no slots to fill), with the decider's runtime guards reduced to the genuinely dynamic checks (hash equality).
+
Identity as a first-class type StreamKey owns build, parse, and render; no zombie Observations, no hand-typed kind:id labels, no silently empty seed keys.
+
Zero-value doctrine kept, not pointerified MOS 0, CostMicros 0, agent DurationSecs 0 keep meaning "not reported"; the redesign adds zero pointer fields to domain rows and removes none of the doctrine's guarantees.
+
Every change labeled by blast radius Each improvement is hash-safe, schema-bumping, or event-frozen — and everything in this edition's roadmap is hash-safe, because the identity machinery earned stability and nothing proposed here needs to spend it.
+
Ceremony proportionate to one operator No version columns, no CreatedAt/UpdatedAt on view rows, no repository generics — the versioning that exists (schema constants riding the hash, event envelope version, dual-generation key fallback) is exactly the load-bearing subset.

03Go Data Model

The proposed types. Every declaration below is hash-safe: none changes a hash pre-image, an event payload, or a stored byte; the view change is byte-identical under JSON embedding.

1 · The composed read model (fixes PC-1)

// CallView keeps its exact JSON shape (embedding promotes fields flat):
// native_id, kind, …, mos, cost_micros, cost_currency, insight_summary,
// content_hash — identical keys, identical omitempty, zero migration
// beyond a re-derivable rebuild.
type CallView struct {
    Observation            // embedded: the 14 source facts
    Enrichment             // embedded: cost + insight

    ContentHash ContentDigest `json:"content_hash"`
}

func ViewFrom(obs Observation, enr Enrichment) CallView {
    return CallView{
        Observation:  obs,
        Enrichment:   enr,
        ContentHash: obs.ContentHash(),
    }
}

// ViewFrom is now lossless by construction: there is no second
// field list to forget a field on. v.Observation and v.Enrichment
// replace Observation() and enrichmentOf outright.

2 · The closed lifecycle (fixes PC-2)

// CallState becomes a sum of the three legal states. The zero value
// is Unobserved — the fold's starting point — and the illegal
// combinations (retired-but-unobserved, enrichment without an
// observation) stop existing.
type CallState struct {
    state interface{ callState() } // nil == unobserved
}

type Unobserved struct{}
func (Unobserved) callState() {}

type Live struct {
    Current          Observation
    CurrentEnrichment Enrichment
    ContentHash      ContentDigest
    EnrichHash       EnrichDigest // "" until first enrichment
}
func (Live) callState() {}

type Retired struct {
    Prior Live          // audit context, read-only from here on
    Reason string        // matches the stored payload field
}
func (Retired) callState() {}

// Record's guards become a type switch; the after-retired branch
// is the Retired case itself, and Enrich on Retired has no field
// to write — the rejection is structural.

3 · Stream identity as a type (fixes PC-3)

type StreamKey struct{ kind SourceKind; native NativeID }

// StreamKeyOf is the only constructor; every path that today builds
// "kind:native" delegates here.
func StreamKeyOf(kind SourceKind, native NativeID) (StreamKey, error) {
    if native == "" || !kind.Valid() {
        return StreamKey{}, newStreamKeyError(kind, native)
    }
    return StreamKey{kind, native}, nil
}

func (k StreamKey) ID() (id.StreamID, error)   // <kind>:<native> via id.ParseStreamID
func (k StreamKey) String() string      // the display form: 5 hand-typed labels retire
func (k StreamKey) IsZero() bool      // SeedsFor rejects instead of dropping

func (o Observation) StreamID() (id.StreamID, error) {
    key, err := StreamKeyOf(o.Kind, o.NativeID)  // delegates
    if err != nil { return id.StreamID{}, err }
    return key.ID()
}

type EnrichmentSeed struct {
    ConversationID string
    CallControlID  string
    Stream         StreamKey   // was StreamKey string — brandable now
}

4 · Validation where values are born (fixes PC-4)

func (e Enrichment) Validate() error {
    if (e.CostMicros > 0) != (e.CostCurrency != "") {
        return newInvalidEnrichmentError(e) // cost pairs with its unit
    }
    if e.CostMicros < 0 {
        return newInvalidEnrichmentError(e) // detail records never bill negative
    }
    return nil
}

// NewEnrichCommand and the decider's Enrich — one line each.

05Validation Layer

Where invalid states become unrepresentable — and where they deliberately stay runtime-checked, because the value must survive a JSON round-trip through append-only history.

Enforced at construction (compile-time or first breath)

StreamKeyOf rejects empty kinds and native ids — a key that cannot address a stream cannot exist. Enrichment.Validate (new) makes the cost-without-currency enrichment unrepresentable at the only ingress (NewEnrichCommand). The closed CallState union makes retired-appends and enrich-without-observe unrepresentable in the fold. Commands already validate observations at construction (NewRecordCommand → Validate → StreamID), so this layer extends an existing seam rather than adding one.

Deliberately still runtime: event payload decode

Fold state and payloads are reconstructed from stored JSON on every replay; struct types must stay constructible and zero-valued there, and history must never be re-validated (old events are trusted bytes — a call.fold.unknown_event corruption answer is the only guard the fold needs). Validation lives at ingress: the four mappers plus the command constructors. That split — validate on the way in, trust on replay — is the correct shape for an append-only log and is preserved untouched.

Still hash-gated: identity itself

ContentHash equality remains the decider's no-op answer, and nothing in this redesign touches the pre-image: schema token, field names, length prefixes, conditional MOS, whole-second turn times are all unchanged. The contentHash(schema int) test seam keeps proving that a bump moves the hash.

07Anti-Patterns

Traps to avoid while adopting this model.

Don't "fix" zero-means-not-reported with pointers

Replacing MOS/CostMicros/DurationSecs zero-sentinel semantics with *float64 / optional structs would change JSON, change the hash pre-image story, and break every dashboard denominator that exists to interpret the convention (QualityRollup.DurationReported). The convention is the contract.

Don't re-type event payload fields

History is append-only: CallRetired.Reason stays a plain string even though the command side brands RetentionReason; TurnRole constants must never be re-numbered or renamed. New payload fields may be added (they decode as zero in old events — that is how SourceEvents landed); existing names, types, and bytes are frozen. Hashed additions need the ObservationSchemaVersion bump plus one refresh backfill, never a silent edit.

Don't validate replayed events

The fold trusts stored bytes; validation belongs to ingress (mappers, command constructors). A Validate call inside Apply would turn one corrupt-but-historical event into a permanent replay failure — the corruption family answer (call.fold.unknown_event) is the fold's only contract.

Don't rebuild the mirror inside the union

When composing CallView, embed — do not redeclare promoted fields "for clarity." A single redeclared field (shadowing the embedded one) silently reintroduces the two-lists-to-update problem this edition exists to retire.

Don't hand-type a sixth kind:id label

Every new diagnostic that needs to name a stream must go through StreamKey.String(); the "\x00" dedupe separator variant is the one legitimate divergence (it is a key, not a label) and should be built from the same StreamKey value.

08Migration Roadmap

Ordered smallest-blast-radius first. Every step is hash-safe and history-safe; none needs a schema bump or an event migration.

1

StreamKey type + StreamKeyOf constructor

internal/calls: introduce the type, delegate Observation.StreamID through it, migrate the three zombie sites (representative, detail join, retire command) and the five label sites. EnrichmentSeed.Stream becomes branded; SeedsFor rejects a zero key loudly instead of dropping it. Pure code motion; no behavior change.

2

Compose CallView; delete the mirror

Embed Observation + Enrichment, delete ViewFrom's and Observation()'s field lists and cli.enrichmentOf, keep the round-trip test (it becomes a proof of embedding, not a guard of labor). Verify stored JSON is byte-identical with a fixture assertion, then rebuild the disposable index via cli.ResetReadModel per the runbook. The additive-only refresh detector stays — it polices hashed-vs-unhashed drift, which embedding does not remove.

3

Enrichment.Validate wired into NewEnrichCommand and Enrich

One new validation plus one call site pair; the enrich pass's targetEnrichment is the natural place to also assert the pairing before dispatch. Zero effect on existing streams (all stored enrichments already pair correctly).

4

Closed lifecycle union in the decider

Rewrite CallState as the three-variant sum, port Record / Enrich / Retire to type switches, keep every rejection code and the no-op semantics identical (the scenario and rapid tests pin them). Fold state only — events, hashes, and replay behavior unchanged.

5

AgeGate retires into retention.Policy

GateIngest takes a Policy; AgeGate is deleted; the serve-poller flag wires Policy{MaxAge} directly. Update DOMAIN_LANGUAGE's age-gate row to name the single type.

–

Explicitly not on the roadmap

ObservationSchemaVersion 3 (nothing proposed needs it); TurnRole re-typing (event-frozen); pointer-ifying zero-means fields (doctrine); version/timestamp columns (ceremony at this scale); generics across the stats types (no shared shape). Recorded here so the next review can check this restraint against fresh evidence.

09Conclusion

“The identity machinery is finished — the remaining debt is that the read model still writes the domain out by hand.” Six weeks after the first edition, every hash-level promise held: pre-image encoding is canonical, roles are typed without moving a byte, and history replays unchanged through two schema generations of row keys. What this pass found is older and simpler — a mirror that tooling was built to tolerate, a lifecycle the guards remember so the types don't have to, and an identity that works but was never named. All three can be paid down without touching a single hashed byte, which is exactly the standard the first edition set.

00Summary

pbx-lens is a small, deliberately single-domain event-sourced monolith, and its skeleton is unusually healthy for its size: the import graph is an acyclic, single-direction pyramid with the domain package internal/calls at the base (zero internal imports, zero infrastructure imports, afferent coupling 11, instability 0.00), a 119-line composition root (internal/app/app.go, ADR-0123) as the only wiring point, and consumer-side interfaces at the two volatile edges (full-text search, the Telnyx HTTP client). Every doctrine that the binding docs promise — disposable index, read-time call join, representative-row collapse, single-process sqlite — is visibly enforced by the structure, not just written down.

The debt is concentrated, not diffuse. internal/web carries 7.4k production LOC across eight concerns — HTTP serving, the entire identity bounded context (own sqlite database, own upstream library), the query/view-model layer, analytics, CSV export, the recording proxy, ops telemetry, and caching policy — and it absorbed 69 of the last 100 commits' Go-file touches. Two smaller misalignments ride along: the serve composition (middleware chain, security headers, systemd install) lives in cmd/pbx-lens/serve.go instead of internal/cli where the documented command-layer convention puts it, and the web layer imports the Telnyx ingest mapper for recording correlation — the one presentation-to-ingest edge in the graph.

The bottom line Average 3.7 — “Good”: no urgent restructuring needed. There is no P0: nothing cycles, nothing points the wrong way, nothing blocks development. The single highest-leverage move is three mechanical extractions that carve internal/web into its natural packages (identity, query, serving) — all S-to-M effort, all independently landable, none requiring the go.mod split the 2026-10-11 HOLD decision correctly defers.

◆What's already excellent

Measured, not impressionistic — each item cites the structural evidence that backs it.

+
A pure domain base at instability 0.00 internal/calls (1,173 prod LOC) imports zero internal packages and zero infrastructure: its entire import set is stdlib (context, fmt, hash, encoding/hex, strconv, strings, time) plus the go-cqrs-lite contracts and go-error-family. Eleven packages depend on it; it depends on nothing. Dependencies point strictly toward stability — the Martin pyramid, verified by the measured DAG.
+
One composition root, 119 lines internal/app/app.go declares the whole domain (4 events, 3 commands, 1 projection) as data, and system.New is the only wiring point (ADR-0123). Production and tests boot from the same DomainConfig() — the test harness cannot drift from production wiring.
+
Interfaces exactly where volatility lives Only two prod interfaces exist — web.Searcher (FTS5 behind the consumer) and web.RecordingFetcher (the Telnyx HTTP client behind the proxy) — and both sit on the edges where an implementation actually could change. No interface-everywhere ceremony.
+
Per-source ingest packages with a shared spine cdr (370 LOC), webhook (182), agent (195), telnyx (672) each own one mapper behind the shared scaffolding in the ingest root package (Result, NewScanner/EachLine, 64 LOC). Adding a source touches exactly one mapper package plus mechanical wiring.
+
Cheap isolation by construction dsn == "" boots the in-memory engine — the one deploy knob — so every package tests against the real composition root with no mocks, no containers, no full system boot. The bounding doctrine (keyset pagination, 5k-row streaming pages, FTS5, bounded tables) is architectural, not aspirational.
+
No grab-bag packages No utils, common, helpers, or shared anywhere. The closest thing to a utility package — internal/wire — holds exactly one concept (FlexTime, 45 LOC) and earns its name.

Direction check (the highlight test): the domain package passes perfectly — no database, net/http, crypto, or framework-runtime imports reach internal/calls; the sqlite engine registers via blank import in the composition root (internal/app), which is exactly where ADR-0123 puts it. Two edges miss the ideal:

  • internal/web → internal/ingest/telnyx: the read side reaches into a write-side mapper package for recording correlation (RecordingByCallControl) and WAV-stem resolution — shared vocabulary that belongs at a read-side seam.
  • web.Register takes the concrete *system.System, and queries.go folds reads through metaengine directly. Framework types are woven through the presentation layer rather than isolated behind a read-model interface (mitigated: the read path is pure query, and calls.LookupView centralizes record-key handling).

Change ripple (last 100 commits): docs lead (96 — an auto-commit artifact), but among Go paths internal/web absorbed 69 file-touches versus 18 for cmd/pbx-lens and 16 for internal/oidclogin; every other Go package took ≤6. The hot spot and the god package are the same object — the strongest possible signal for where a split pays off.

04Findings

Ordered by impact. Each follows the finding → impact → recommendation → effort format; no P0 exists — that absence is itself a finding.

P1 · God package

internal/web is four packages wearing one name

internal/web/* · 19 prod Go files + 7 templ · 7.4k prod LOC · 41 exported decls · 69/100-commit churn

Finding: one package contains the HTTP serving and routing (server.go, 846), the entire identity bounded context (userauth.go, 534 — its own sqlite database, session gate, CSRF, WebAuthn/RPID derivation, even *sql.DB PRAGMA tuning), the query/view-model layer (queries.go, 712), the analytics suite (dashboard.go 560, quality, segments, anomaly, coverage, freshness ≈ 1.3k), the streaming CSV export, the recording proxy, ops telemetry, and the caching/ETag policy.

Impact: every concern is a merge-conflict neighbor of every other — measured as 69% of recent Go churn in one package; the 8.4k-loc test suite re-runs for any of them; and the documented identity bounded context (DOMAIN_LANGUAGE § 2026-11-12) has no code boundary to point at, so its durability guarantees (backup, purge-untouchability) rest on convention inside a package whose other half changes daily.

Fix: three mechanical extractions (roadmap P1) (1) userauth.go + its five test files → internal/identity — it is already a self-contained constructor pair (OpenIdentity/Identity.Register); (2) the read side (queries, dashboard, quality, segments, anomaly, coverage, freshness ≈ 2.9k LOC) → a query package with exported view models; (3) what remains (serving, templ, export, recording, ops, caching) is a coherent ~3k package. Effort S+M total; ordering: identity first (smallest, independently landable), query second.
P1 · Layering drift

Serve composition lives in the binary, not the command layer

cmd/pbx-lens/serve.go (590 LOC) · cmd/pbx-lens/ops.go (284)

Finding: the documented convention (AGENTS.md § Structure) puts the CLI command layer in internal/cli with cmd as thin flag shells — and 8 of 10 subcommands follow it. But serve and ops carry real composition in package main: the appkit middleware chain, security headers, systemd install, poller boot, and the backup/retention orchestration.

Impact: the serve wiring — whose ordering/ETag/ no-cache doctrine docs/http-stack.md calls load-bearing — is untestable without the binary and invisible to the internal- package conventions; the inconsistency also doubles the mental model of "where does a command live".

Fix move the composition body of serve.go/ops.go into internal (cli or a new internal/serve), leaving flag parsing in cmd exactly like ingest-cdr does today. Effort S–M; independently landable; pairs naturally with finding 1 but has no hard ordering dependency.
P2 · Direction smell

Read side reaches into a write-side mapper

internal/web → internal/ingest/telnyx · RecordingByCallControl in ingest/telnyx/map.go

Finding: the web layer imports the Telnyx ingest mapper for recording correlation (RecordingByCallControl, DOMAIN_LANGUAGE's own term) and the WAV-stem resolution rules — the only presentation→ingest edge in the graph.

Impact: the ingest subpackages stop being purely write-side, and a domain concept's canonical home is a file named after wire parsing. Today the cost is cognitive; the risk is future drift between what the mapper correlates at ingest time and what the detail page correlates at read time.

Fix relocate the correlation vocabulary (call_control_id matching, WAV stems, {uuid}_* sweep) to a read-side home — calls or a small internal/recording — and let both sides import it. Effort S; after finding 1 only to avoid double-churning web.
P2 · Reuse ceiling

Query models are package-private inside the UI

internal/web/queries.go · ListCallsQuery, DashboardStats et al.

Finding: the read-side vocabulary — list filters, dashboard stats, denominators — is lowercase and unexported inside internal/web. The export path reuses it in-package, but no future consumer (an API lane, an automation, the ROADMAP's "any question answerable" north star) can compose these queries without importing all of web or copying the logic.

Impact: composability, not correctness — the single-operator UI is fine today; the ceiling bites the day a second consumer arrives and the cheapest path becomes copy-paste (the thing the art-dupl gate exists to police).

Fix this is finding 1 step (2): moving the read side to its own package with exported models solves it as a side effect — no separate work item unless step (2) is declined.
P3 · Hygiene

Dead test helpers and diagnostic noise

internal/calls/domain_test.go (mustEvents, decide unused) · internal/app/app.go (gopls infertypeargs ×3)

Finding/Impact/Recommendation: gopls flags two unused test helpers in the domain package and three unnecessary type-argument hints in the composition root. Zero runtime cost; pure signal-to-noise for the next reader. Effort S — one dead-code sweep, no ordering.

05What the solution could look like

The target is not a rewrite and not a go.mod split — the 2026-10-11 HOLD stands (single domain, zero external Go consumers, revisit triggers unfired). It is three package moves that give each existing concern its own name:

After the moves, web churn localizes to serving+templ, identity gains a code boundary matching its documented durability guarantees, and the read models become importable by any future consumer.

06Action roadmap

P0 — none. No cycles, no domain→infrastructure violations, no structure-caused incidents. That is the finding, not an omission. P1 and P2 in landing order:

1

Extract identity → internal/identity P1 Effort S–M

Move userauth.go and its test cluster (auth_test, userauth_*_test, auth_oidc_test) to a new internal/identity; cmd/serve.go and web's Options are the only callers. Impact: code boundary for the documented bounded context; removes *sql.DB wiring from the presentation layer; first shrink of the churn king. No ordering dependency.

2

Split web's read side → internal/query P1 Effort M

Move queries.go, dashboard.go, quality.go, segments.go, anomaly.go, coverage.go, freshness.go (~2.9k LOC) with exported view models; web imports query and keeps serving + templ. Impact: reusable read vocabulary (finding 4 resolved as a side effect); the 8.4k-loc test suite splits along the same seam. Land after step 1 — smaller web first means smaller diffs.

3

Move serve composition out of cmd P1 Effort S–M

serve.go (590) and ops.go (284): composition body → internal (cli or internal/serve), flag shells stay in cmd — exactly the shape ingest-cdr already has. Impact: the middleware chain and systemd wiring become testable and convention-compliant. Independent; convenient to land beside steps 1–2.

4

Recording correlation to a read-side home P2 Effort S

RecordingByCallControl + WAV-stem rules out of ingest/telnyx/map.go into calls or internal/recording; both sides import it. Impact: removes the only presentation→ingest edge; ingest subpackages become purely write-side. After step 1 (avoid double-churning web).

5

Dead-code sweep + re-score P3 Effort S

Delete unused test helpers (calls/domain_test.go: mustEvents, decide), accept gopls infertypeargs hints in app.go. After steps 1–3 land, re-run this review's measurement set (five commands) and re-check the go.mod HOLD triggers — an external Go consumer of the new query package would be exactly the trigger the 2026-10-11 decision names.

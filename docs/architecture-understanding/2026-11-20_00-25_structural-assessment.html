00Summary

pbx-lens is a small, deliberately single-domain event-sourced monolith, and its skeleton is unusually healthy for its size: the import graph is an acyclic, single-direction pyramid with the domain package internal/calls at the base (zero internal imports, zero infrastructure imports, afferent coupling 11, instability 0.00), a 119-line composition root (internal/app/app.go, ADR-0123) as the only wiring point, and consumer-side interfaces at the two volatile edges (full-text search, the Telnyx HTTP client). Every doctrine that the binding docs promise — disposable index, read-time call join, representative-row collapse, single-process sqlite — is visibly enforced by the structure, not just written down.

The debt is concentrated, not diffuse. internal/web carries 7.4k production LOC across eight concerns — HTTP serving, the entire identity bounded context (own sqlite database, own upstream library), the query/view-model layer, analytics, CSV export, the recording proxy, ops telemetry, and caching policy — and it absorbed 69 of the last 100 commits' Go-file touches. Two smaller misalignments ride along: the serve composition (middleware chain, security headers, systemd install) lives in cmd/pbx-lens/serve.go instead of internal/cli where the documented command-layer convention puts it, and the web layer imports the Telnyx ingest mapper for recording correlation — the one presentation-to-ingest edge in the graph.

The bottom line Average 3.7 — “Good”: no urgent restructuring needed. There is no P0: nothing cycles, nothing points the wrong way, nothing blocks development. The single highest-leverage move is three mechanical extractions that carve internal/web into its natural packages (identity, query, serving) — all S-to-M effort, all independently landable, none requiring the go.mod split the 2026-10-11 HOLD decision correctly defers.

◆What's already excellent

Measured, not impressionistic — each item cites the structural evidence that backs it.

+
A pure domain base at instability 0.00 internal/calls (1,173 prod LOC) imports zero internal packages and zero infrastructure: its entire import set is stdlib (context, fmt, hash, encoding/hex, strconv, strings, time) plus the go-cqrs-lite contracts and go-error-family. Eleven packages depend on it; it depends on nothing. Dependencies point strictly toward stability — the Martin pyramid, verified by the measured DAG.
+
One composition root, 119 lines internal/app/app.go declares the whole domain (4 events, 3 commands, 1 projection) as data, and system.New is the only wiring point (ADR-0123). Production and tests boot from the same DomainConfig() — the test harness cannot drift from production wiring.
+
Interfaces exactly where volatility lives Only two prod interfaces exist — web.Searcher (FTS5 behind the consumer) and web.RecordingFetcher (the Telnyx HTTP client behind the proxy) — and both sit on the edges where an implementation actually could change. No interface-everywhere ceremony.
+
Per-source ingest packages with a shared spine cdr (370 LOC), webhook (182), agent (195), telnyx (672) each own one mapper behind the shared scaffolding in the ingest root package (Result, NewScanner/EachLine, 64 LOC). Adding a source touches exactly one mapper package plus mechanical wiring.
+
Cheap isolation by construction dsn == "" boots the in-memory engine — the one deploy knob — so every package tests against the real composition root with no mocks, no containers, no full system boot. The bounding doctrine (keyset pagination, 5k-row streaming pages, FTS5, bounded tables) is architectural, not aspirational.
+
No grab-bag packages No utils, common, helpers, or shared anywhere. The closest thing to a utility package — internal/wire — holds exactly one concept (FlexTime, 45 LOC) and earns its name.

04Review Doctrine

Hard rules

Fix on sight when safe; verdict + ticket when not. No verschlimmbessern: every change must leave the tree verifiably no worse (gates after every lane). Owner-gated items (release shape, CSP flip, PII, stamp churn) are NOTED, never executed. Concurrent sessions are the norm: verify current file state immediately before each edit; the daemon may commit mid-pass.

What counts as a finding

Type-safety first: states that should be unrepresentable, booleans that want enums, raw strings that want typed kinds. Split brains (duplicate truths), hand-rolled record keys, unbounded reads, dishonest denominators, docs that claim what code does not do. Strengths are recorded too — they are load-bearing.

The bottom line

Both fleet-score gaps were closed on 2026-11-04 — the audit worked.
  1. go-error-family went 45 → 82/100. The CLI boundary now maps families through HandleError (transient projection failures exit 75 EX_TEMPFAIL), one family-aware writer replaced the 14 hand-mapped web sites and their err.Error() bodies, structured logging rides LogErrorContext, and errorfamilytest replaced three hand-rolled assertions.
  2. server_timing went 33 → 67/100 and the false doctrine is gone. The hand-rolled wrapper is deleted, ServerTimingMiddleware() is wired (which also restored r.Pattern propagation), and every document that claimed the constructor did not exist has been corrected.
Refresh 2026-11-11: the cqrs-htmx flip-trigger FIRED — the fleet's first verdict upgrade. The 2026-11-11 operator order replaced the htpasswd gate with the cqrs-htmx identity stack (usermgmt + loginpage + webauthn, leaf modules only, root stays indirect): an event-sourced operator account, passwordless WebAuthn login, SQL sessions, and MaxUsers = 1 single-operator registration — exactly the adoption shape the original report's guardrails demanded. The same refresh: re-verified every pin against the module proxy (go-etag's “v0.7.0 upstream” claim corrected — the root tag is not a submodule release; v0.6.1 is current), recorded go-cqrs-lite's four trailing modules and appkit's v0.10–v0.12 deltas, expanded the go-error-family/httputil censuses for the adoption (10 new bootstrap Rejection sites; CSRFMiddleware now wired), and wrote the three missing reports (go-datastar, cmdguard, httputil/endpoints — all REJECT with reasons).

Used-pin currency at refresh: 6 of 8 — go-cqrs-lite holds four modules back (single-writer CLI needs none of the concurrency fixes in the pending waves) and go-appkit holds three minors (the bump carries the Server-Timing de-duplication); both are scheduled holds in their reports, not drift.

internal/web/timing.go:16-25 · docs/http-stack.md:32-34 · AGENTS.md (corrected) · prior audit finding #2

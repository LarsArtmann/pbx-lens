## Version-bump watchlist (run on EVERY templ-components bump, in order)

1. **Regenerate the Tailwind corpus:** `node scripts/gen-tc-classes.js` — the
   corpus resolves the module cache and version THROUGH the go toolchain
   (`go env GOMODCACHE` + `go list -m`), so it cannot go stale on a pin
   bump; a scan that finds nothing exits non-zero instead of writing an
   empty corpus (the v1.21.0-era hardcoded paths once regenerated EMPTY
   and the drop went unnoticed). Rebuild CSS after: `nix run .#update-styles`.
2. **Re-audit this map against the new pin:** `ls` the new module cache for
   every ABSENT/rejected row (SegmentBar, FilterBar, SegmentedControl,
   utils/format, LineChart, DataTable, AppShell) — flip rows that shipped,
   with a one-line why-not for flips that stay rejected.
3. **Re-check the hand-rolled thin pieces** for library equivalents:
   `transcriptMatchLog` (waits on a ScrollbackLine id/class hook),
   SegmentBar stand-in, anything else carrying a "hand-rolled" status here.
4. **Re-read the open templ-components filings** (#48 BarChart collapse,
   #49 TableRow focus ring, #50 skill drift, #51 ScrollbackLine hook) — a
   fix upstream deletes a local workaround (`!items-stretch` class args,
   the focus-visible CSS, the hand-rolled match log).
5. **Goldens:** markup changes from the bump are deliberate — refresh with
   `GOEXPERIMENT=jsonv2 go test ./internal/web/ -run 'TestGolden' -update`,
   REVIEW the diff, then commit; the plain suite must go green without
   `-update` afterwards. (The pattern must cover TestGoldenOpsPage —
   `-run TestGoldenPages` silently skips it.)
6. **Art-dupl baseline:** a bump that changes the clone set turns the CI
   duplication gate red — review the new/shifted groups, then refresh with
   `art-dupl baseline -t 4 --min-lines 2 . --baseline-path scripts/art-dupl-baseline.json`
   (gate contract + acceptance table: docs/art-dupl-baseline.md).
7. **Filings-ledger state check (the step the v1.26.0 sweep skipped):** run
   `gh issue list`/`view` over every OPEN templ-components filing in
   docs/upstream-filings.md and update the ledger's state-check block — a
   closure upstream (like #52) means a local workaround retires in the same
   bump, not later. Done 2026-11-12: #48/#49/#51/#55/#63/#50 all CLOSED,
   but every fix merged 2026-11-06/07 — AFTER the v1.27.0 tag — so the
   workarounds stay and the retirements are queued on the next bump.
8. **Two-module templ gate (v1.27+):** DONE 2026-11-12 — templ v0.3.1100
   - templ-components v1.27.0 landed together (goldens + codegen
     re-baselined in the same change); upstream now ships

     templ pins stay manual-only (dependabot banned); the NEXT coordinated
     bump retires the #48/#49/#51/#63 workarounds — watchlist steps 2-4+7
     again on that bump.

## Corpus trim decision (T17, 2026-10-12): KEEP the full corpus

Measured: the corpus carries 6,405 class lines at v1.21.0 (every class
string in templ-components, used or not; 7,637 at v1.24.0); styles.css
builds to ~105,000 bytes minified — ~17,300 bytes gzipped on the wire. A
corpus trimmed to pbx-lens's reachable classes would save roughly that
gzip delta, and the cost is a second staleness axis: every component
adoption AND every bump would need a re-trim, and a stale TRIMMED corpus
silently drops classes exactly like the stale FULL corpus that shipped the
2026-10-12 hamburger/dark-shade breakage — except the goldens pin markup,
not pixels, so missing CSS is invisible to the whole test suite. For a
single-host internal tool whose CSS revalidates at 304s, ~17 KiB on the
wire once per index change is noise. Revisit only with a real trigger
(CSS on a billed CDN, or a cold-start budget) AND a reachability test
that fails the build when a rendered class is missing from the corpus.

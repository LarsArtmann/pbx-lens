01 Summary

Both libraries are used correctly wherever they are used. The headline is not a gap in adoption but a single missed capability that had a measurable cost: testkit.Serve runs the service's full shutdown, including the production 5 s drain delay, unless the service was built with testkit.NewService. serveTestStack built it with appkit.NewService, so every stack-level test paid 5 s at teardown — TestServeStackEndToEnd measured 5.04 s of which 5.005 s was drain. Adopting testkit.NewService at the three test call sites cut the package from 10.5 s to 0.81 s (and that single test to 0.02 s). This is appkit#26's documented trap, re-paid here for a month.

Why the score is not higher. The denominator is capability coverage, not correctness. Every capability pbx-lens uses from go-appkit is used as the library intends (lifecycle, drain, middleware stack, health, metrics, version, NoTimeout, testkit). The four unwired seams — ReadyCheck, OuterMiddlewares, StartHooks, ShutdownHooks — are enhancements with no current consumer, not misuses. Two capabilities are deliberate non-adoptions (InitLogger: slog is the house log standard; the error-family re-exports: this repo imports the family directly).

04 Findings

F1 · FIXED THIS PASS

Every stack-level test paid the production 5 s drain delay

testkit.Serve runs the service's complete shutdown, and appkit's production default carries a 5 s DrainDelay. serveTestStack built the service with appkit.NewService, so the drain was paid once per call — including the two recording tests that bypassed the helper. Measured: TestServeStackEndToEnd = 5.04 s (5.005 s drain); package total 10.5 s. After switching all three sites to testkit.NewService (v0.9.0's test-safe defaults: ephemeral loopback addr + NoDrainDelay): the single test = 0.02 s, the package = 0.81 s.

This is exactly issue #26's teardown trap, and AGENTS.md already lists go-appkit#26 as CLOSED / fold-in-ready — the fold-in was simply never performed. It is performed now.

Guard against regression: the only way back is a new test calling appkit.NewService; the census below keeps that visible.

F2 · candidate

ShutdownHooks would make teardown ordering explicit

Today the serve teardown rides defer ordering inside runServe (serve.go:110 ctx cancel, :117 system cleanup, :128 FTS index close, :195 poller stop). It works, and the ordering is documented — but a ShutdownHooks registration would make "stop the poller, then close the index, then close the store" explicit at the composition site instead of implied by LIFO. Cost: ~15 lines. Value: readability, not correctness.

F3 · candidate

Typed URL values would express intent (no bug today)

templ.URL/SafeURL are unused; hrefs are plain strings built with url.PathEscape and url.Values. Because they are strings, templ escapes them — safe, and the pager tests already unescape &amp; when asserting. The win would be readability (a typed URL cannot be confused with a label) plus JoinURLErrs for the error paths. Deferred: it touches every href builder for no behavioural change.

F4 · documented incompatibility

templ.GetNonce is not wired to this stack's nonce

httputil.Nonce stores its nonce under its own context key, and internal/web/nonce(r) reads it through httputil.NonceFromRequest. A handler that reached for templ.GetNonce(ctx) would silently get "" — in nonce mode that is a blocked script, not a visible error. Recorded in docs/http-stack.md's orbit (this report) so the next person does not "simplify" it.

F5 · observation

Zero hand-written script blocks is a strength, not an absence

grep -c '<script' internal/web/*.templ = 0. Every inline script on every page comes from templ-components (ToastContainer, theme toggle, mobile menu, row-href singleton) and receives the request nonce through a prop. That is why templ's ComponentScript surface stays unused: there is nothing of ours to emit.

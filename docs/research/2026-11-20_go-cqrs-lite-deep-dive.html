00Summary

go-cqrs-lite is the load-bearing half of pbx-lens' dependency graph: 14 direct modules spanning the composition root (system/v4), the read model (metaengine/v4 + sqliteengine + projectionadapter), the write side (event, command, decider, id, record), the projection workers (projectionhost, storage), the test harness (scenario, systemscenario) and the docs renderers (catalog). This audit re-verified every import site at HEAD (2026-11-20), read the pinned source in the module cache, and graded 49 capability rows — 27 applicable, 22 fully leveraged, 5 partially used, zero missed or misused. The prior fleet report scored the runtime core 92/100 (23 of 25); this report's 91 is the same posture re-derived under a narrower census that adds two rows the fleet did not grade (engine-native cursor pagination; the system health surface).

The bottom line Adoption is reference-quality and needs no corrective work. The two highest-leverage moves are both additive: take the four-module pin wave (system, metaengine, sqliteengine, catalog — verified to carry no used-surface change), and evaluate TypedReader.ScanPage's compound cursor as a replacement for the ~95 lines of hand-rolled keyset-pagination machinery in internal/web/queries.go.

Prior reports this one supersedes (newer and narrower wins): the runtime-core half of docs/review/libs/go-cqrs-lite.md (2026-11-04 fleet audit, refreshed 2026-11-11/12; score 92/100, all findings since closed) is superseded here — its census was re-verified at today's HEAD and its closed findings are carried as history. The catalog + testing-modules half remains owned by docs/research/2026-10-24_go-cqrs-lite-catalog-testing-modules-deep-dive.html (58/100 at its pin; execution errata record the closures). The fleet index (docs/review/libs/index.html) keeps the pooled library-wide view.

Partially Used · Medium impact

Engine-native keyset pagination unused — the export/list walk hand-rolls tie handling

internal/web/queries.go:214-241, 296-410 · library: metaengine/v4@v4.23.0 typed_reader_cursor.go:30-67, cursor.go

What the library offers: TypedReader.ScanPage returns a *Cursor alongside each page. When the engine issues a compound SortKeyCursor (sort value + byte key of the last row) it is returned as-is, so tie-heavy datasets paginate with neither drops nor duplicates — and the sqliteengine at the pinned v4.8.0 does issue compound cursors (engine.go:499, planned.go:313). Cursor.Encode() is a URL-safe opaque string built for exactly the HTTP-pagination case.

What the project does instead: ~95 lines of machinery — newerPageCursor probe scan (queries.go:214-241), the seen-map tie set, advanceCursor, and a loud lens.web.export_cursor_stalled rejection for the pathological one-nanosecond-group case (queries.go:296-345). The hand-rolled walk also binds time cursors as RFC3339Nano strings to dodge the known sqlite time-binding divergence (queries.go:439-448; upstream issue pending) — a compound cursor binds the engine's own sort value, sidestepping that class for the cursor itself (user from/to filters still need the string binding).

Recommendation Prototype ScanPage + WithCursor for streamViews; the per-source export contract and the representative collapse wrap the walk and are unaffected. Verify one behavioral nuance first: the stall error currently names the colliding stream ids (stallContext), which the library path would replace with a no-drops guarantee instead of a loud failure — decide whether that diagnostic is worth keeping. 
// Today: hand-rolled inclusive-cursor page + seen-set dedupe

Partially Used · Low impact (deliberate)

system.HealthCheck exists; pbx-lens hand-rolls a deliberately stricter readiness

internal/cli/system.go:146-174 · library: system/v4@v4.18.0 introspection.go:164-190

System.HealthCheck covers stopped-ness, engine pings, and WorkerFailed — the documented Kubernetes-probe entry point. pbx-lens instead composes ProjectionWorkersReady over host.Status(), treating WorkerBackoff as broken too (the read model is behind until the restart lands). The divergence is documented in the code (system.go:131-145: the deliberate inverse of the drain predicate). Impact of adopting the library call: it would loosen readiness (backoff → healthy), so the hand-rolled predicate stays until upstream grows backoff sensitivity — worth an upstream filing.

Partially Used · Low impact (owner-gated execution)

internal/cli/system.go:91-97 · docs/runbooks/reset-rebuild.md

The row stays Partially Used by the same reasoning — re-score to Full when the prod run lands.

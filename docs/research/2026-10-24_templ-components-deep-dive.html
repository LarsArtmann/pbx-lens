00Summary

pbx-lens treats templ-components as a system, not a CSS kit. Thirty-three distinct components across layout, navigation, display, forms, feedback, htmx, icons and utils are wired into the six page surfaces; the token chain is re-skinned to the signal palette in exactly one place; and every library trap the codebase has met so far is pinned by a named guard (CSS gate, palette gate, relative-time contract, heading-order probe). This is what a model consumer looks like — with two gaps worth closing.

The bottom line The one real gap is utils/format: pbx-lens hand-rolls clockDuration, compactDuration, stringOrDash and percent (internal/web/calls.templ:383-422, internal/web/dashboard.templ:711-714) while the pinned version already ships format.ClockDuration, format.CompactDuration, format.StringOrDash and format.Percent — and the ops page already uses two of them. Result: the product renders two different compact-duration dialects for the same concept ("1m" on /ops vs "1m00s" in the staleness banner). Second: the pin is one minor behind, and v1.24.0 (2026-10-23) ships ARIA-nesting fixes for two components pbx-lens renders today (Heatmap, CopyButton).

Missed opportunity · High impact

utils/format is duplicated by hand — two duration dialects ship in one product

internal/web/calls.templ:383-422 · internal/web/dashboard.templ:711-714 · adopted half: internal/web/ops.go:202, ops.templ:65, ops.templ:169

The pinned version ships format.ClockDuration, format.CompactDuration, format.StringOrDash and format.Percent (utils@v1.23.0/format/format.go:75-155, tested upstream). pbx-lens adopts CompactDuration and Percent on the ops page only, then hand-rolls four twins elsewhere: clockDuration (identical output sub-day; the library adds a ≥1d tier), compactDuration (renders "1m00s"/"12h05m" where the library renders "1m"/"12h5m" — so /ops and the staleness banner disagree on the same concept), stringOrDash (byte-identical), and percent (identical output today because every ratio source guards zero, but missing the library's NaN→"—" hardening). Roughly 40 consumer lines duplicate a module already in the dependency graph. Honest correction: this morning's dedup pass accepted clockDuration/compactDuration as "different documented business rules" — the library alternative shows the better resolution is deletion via adoption. 

// Before: two dialects, four local twins
func compactDuration(d time.Duration) string {
    if rounded < time.Minute { return rounded.String() }
    ...
}

// After: one dialect, owned upstream
import "github.com/larsartmann/templ-components/utils/format"
format.CompactDuration(age)  // "42s", "1m30s", "12h30m" — everywhere
Fix Replace the four helpers with format.*; keep mosGaugePercent (domain mapping, not a duplicate); refresh goldens — compactDuration's copy changes ("1m00s"→"1m", "12h05m"→"12h5m") while clockDuration and stringOrDash are byte-identical for all reachable inputs; flip the adoption map's format row (it still says "not yet adopted" while two functions are in service).

Rough edge · Medium impact

RelativeTime renders zero-time noise for a poller that never ran (#52)

internal/web/ops.templ:123 · upstream #52 OPEN

The ops page explicitly models "unknown" (StaleKnown=false renders a neutral verdict badge) — but the "Last pass" row renders RelativeTime(p.LastPass) unguarded. A zero time.Time produces "Jan 1, 0001"-based text; upstream has no EmptyText escape (#52 open). Reachable between serve start and the first completed poll pass, and in any never-polled state. 

// Before: zero time renders date noise
{Term: "Last pass",
    DetailComponent: display.RelativeTime(display.RelativeTimeProps{Time: p.LastPass})},

// After: the modeled state gets words, not noise
if p.LastPass.IsZero() {
    row.Detail = "never"
} else {
    row.DetailComponent = display.RelativeTime(...)
}
Fix Guard consumer-side now; comment on #52 with the ops-poller use case — the EmptyText escape belongs upstream too.
Upstream limitation · Medium impact

BarChart (vertical) rides two open filings on a live local workaround

internal/web/dashboard.templ:441 · #48 OPEN · #59 OPEN

Today's 30-day volume series works; MOS bars or cost series with negatives would hit the wall.

Action Keep the workaround and its comment; re-read both filings on every bump (watchlist step 4) — their landing deletes local code.

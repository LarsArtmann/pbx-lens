00Summary

Before the audit, pbx-lens reached go-etag and httputil only through go-appkit’s default middleware; server_timing sat in go.sum as a test dependency; nothing answered a conditional GET, carried a Server-Timing header, or compressed a body. The audit read all four modules at their pinned versions (module cache, not HEAD), mapped every unused knob, and executed the Pareto plan: conditional GET everywhere with a per-route skip policy, Server-Timing on every route, gzip ordered outside the ETag, /version and /metrics turned on, and — the real find — a 30-second request deadline that silently truncated the no-row-cap exports and long recording downloads.

The bottom line The stack is now used to the max at the pinned versions: every shipped page, poll fragment, and asset revalidates with 304s; every route names its cost in a Server-Timing header; and the stream contracts hold because WriteTimeout: NoTimeout removed the default deadline. Everything the audit considered and did NOT adopt is doctrine-checked in the appendix — do not re-litigate casually.

◆What pulled weight after the pass

+
go-etag/server: body-hash 304s with a skip policy Pages, htmx poll fragments, and static assets answer If-None-Match with zero body bytes; the ever-changing staleness/freshness bodies and the unbounded export and recording streams are deliberately skipped (internal/web/caching.go).
+
server_timing: a named cost per route query/stats/fts/count on the read paths, metadata/headers on the recording proxy — the released wiring primitive is WrapServerTiming + MeasureServerTiming (no middleware constructor exists at any released version), which shaped the internal/web/timing.go design.
+
httputil Compression, ordered outer of the ETag q-value negotiation (br > zstd > gzip) with an incompressible skip list; sitting outside the ETag is the library’s ordering doctrine, so tags hash identity bodies and pages drop ~4–6× on the wire.
+
go-appkit knobs that were set to zero Version (GET /version + appkit_build_info), Metrics (Prometheus /metrics, unauthenticated by explicit opt-in), and WriteTimeout: NoTimeout — the library’s own answer for stream services.

01Findings

The audit found one real bug and two design constraints worth recording. All findings are closed; they stay here because the reasoning is the reusable part.

Found · fixed same day

The appkit default 30 s WriteTimeout truncated every unbounded stream

cmd/pbx-lens/serve.go · ServiceConfig{Addr} left WriteTimeout at the default

The default deadline sat on every request context. /api/export.{jsonl,csv} honor r.Context() and stream with no row cap, so a large index truncated at 30 s into a silently short file; the recording proxy built its upstream WAV request on the same context, so “body streams unbounded” died mid-song for any slow transfer. Two shipped contracts violated by one forgotten knob.

Fix (shipped) WriteTimeout: appkit.NoTimeout in buildServiceConfig — drops the Timeout middleware while ReadHeaderTimeout and the per-route recording upstream bound (30 s, -recording-timeout) stay.
Constraint · shaped the design

server_timing has no middleware constructor — and loses metrics after the first flush

server_timing v1.0.2, released surface

No released version ships a middleware constructor; the primitive is WrapServerTiming(w, r) plus MeasureServerTiming(ctx, name). Header values flush at first write, so metrics recorded after the first write are lost — streaming routes can only instrument pre-first-write hops. pbx-lens wraps this in internal/web/timing.go once and instruments the named hops at each handler.

Doctrine · graph honesty

Three modules were one flag away, not one rewrite away

go.mod · httputil, server_timing, go-etag/server promoted to direct

All three were already in the module graph via go-appkit; promoting them to direct dependencies added no new module — the same precedent as x/crypto and x/time. The graph now tells the truth about what the code imports.

02The shipped middleware order

The target state the audit proposed is the state that shipped: one constructor, documented order, every knob justified. 

// cmd/pbx-lens/serve.go — buildServiceConfig
ServiceConfig{
    Addr:         addr,
    Version:      version,          // GET /version + build_info
    Metrics:      MetricsConfig{AllowUnauthenticated: metricsOptIn},
    WriteTimeout: appkit.NoTimeout, // stream contracts
    ExtraMiddlewares: append(extras,
        authMiddleware,                       // htpasswd
        web.ServerTimingMiddleware(),         // named per-route costs
        httputil.Compression(compressCfg),    // OUTER of etag (doctrine)
        web.ETagMiddleware(cacheStats, log),  // body-hash 304s + skip policy
    ),
}
Why this order holds Compression outside the ETag is the go-etag README doctrine: tags must hash identity bodies, not encodings. Auth outermost keeps /metrics behind an explicit opt-in (SECURITY.md). The buffered templ render (web.render) is what makes bodies hashable at all — a streaming flush silently disables the 304 contract.

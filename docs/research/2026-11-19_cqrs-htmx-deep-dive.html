Partially used · 3 unset options with visible effect

loginpage.Config: NoRegistration, AccentColor, ThemeFromRequest all unset

internal/web/userauth.go:231-240 (pageCfg) · loginpage/v4@v4.18.0 config.go + handler.go:285

Three options matter for this deployment. (a) NoRegistration: the page shows its registration section whenever WebAuthn is configured (showReg := !config.NoRegistration && hasWebAuthn, handler.go:285) — it cannot know that MaxUsers: 1 closed the door after the operator registered, so the page offers a form that always fails with “registration closed”. The count is available at startup (synchronous drain, ReadModel().Count()). (b) AccentColor: the generated SVG favicon defaults to the library color on an app whose brand is teal (app.css overrides the whole tc palette). (c) ThemeFromRequest: unset means the login page follows prefers-color-scheme, while the app’s ThemeToggle persists to localStorage — which the server cannot read; bridging needs a cookie mirror, so an operator with a localStorage dark choice sees a light login page (and vice versa).

Recommendation Set all three in the existing config block; the theme bridge additionally needs the ThemeToggle’s script to mirror its choice into a cookie (a two-line script change beside the toggle), or accept the mismatch and document it. 
pageCfg := loginpage.Config{
    Service:     service,
    Title:       "Sign in \u2014 pbx-lens",
    Brand:       "pbx-lens",
    Redirect:    "/",
    CSSPath:     "/app.css",
    NonceFromRequest: httputil.NonceFromRequest,
    AccentColor: "#0f766e",                                  // teal-700, the app brand
    NoRegistration: service.ReadModel().Count() > 0,         // door already closed
    // ThemeFromRequest: themeFromCookie,                    // + cookie mirror in ThemeToggle
}
Missed opportunity · low urgency

Identity import/export surface unused — no logical backup beside the file backup

not used anywhere · usermgmt/v4@v4.20.0 import_export.go:86-206 + admin-gated /auth/export (HandlerConfig default RequireAdminRole)

The service ships ExportUsersToJSON/CSV and the AuthHandler exposes them behind the admin role. pbx-lens backs up identity.db at the FILE level (NixOS module, beside the index). A logical export is the restore path that survives a SQLite version jump or a corrupted journal — relevant because identity.db is the one non-disposable database. The capability also covers rebuilds: a fresh host can import the operator instead of re-running first-deploy.

Recommendation Add one operator step to docs/runbooks/identity-first-deploy.md (curl the admin-gated /auth/export after bootstrap, store beside the file backup) — or a small CLI subcommand calling ExportUsersToJSON directly. No wiring change needed; the operator’s first-user account carries the admin role the default authorizer requires.
Partially used · recovery path unexposed

Projection operations: statuses consumed, RebuildProjection unreachable

internal/web/userauth.go:461-471 (Ready/ProjectionStatuses) · RebuildProjection: not referenced in pbx-lens

Ready() folds ProjectionStatuses() into the readiness gate (statuses live/stopped only) — good. But the library’s recovery primitive, svc.RebuildProjection(ctx, name) (stop host, reset checkpoint + read model, replay), has no operator surface: a corrupted read model on the identity context currently means hand-written SQL or a redeploy. The journal is tiny, so a rebuild replays in seconds — the cost of exposing it is one CLI flag.

Partially used · defaults unexamined

SessionTTL / SessionMaxAge left at the 24-hour defaults

userauth.go:205-216 (ServiceConfig without SessionTTL) + :417-436 (HandlerConfig without SessionMaxAge)

The single operator re-authenticates every 24h. That may be the intended posture — but it is a default, not a decision: neither config site sets it and no doc records a choice. A single-operator homelab lens might deliberately choose longer (7d) with passkey-only login, or keep 24h and write it down. Either way it should stop being an accident.

Partially used · low impact

Close() chosen over GracefulClose(ctx) in the shutdown path

cmd/pbx-lens/serve.go:182 (deferred identity.Close) · usermgmt service_lifecycle.go:56 vs :64

Service.Close() stops projections and returns; GracefulClose(ctx) additionally waits out in-flight work within a budget. appkit’s svc.Run owns signals + connection drain, and the deferred Close runs after it — in-flight auth requests have typically finished. The exposure is a narrow race (an auth ceremony mid-dispatch at shutdown). Low priority; note for the next touch of the serve wiring.

00Summary

templ-components is the fleet’s best-adopted dependency and this audit confirms it: all 8 importable packages are in use, all 7 .templ pages are built on the library with zero hand-rolled parallel components, and the disciplined adoption map (docs/templ-components-adoption.md) held through the 2026-11-12 coordinated bump. Of the 8 partially-used rows, 7 are upstream-blocked workarounds for filings #48/#49/#51/#55/#63 whose fixes merged 2026-11-06/07 — after the v1.27.0 tag — and the 8th is version currency itself. The score moved from the fleet report’s 95 to 89 for one honest reason: the denominator grew (38 applicable rows vs the fleet’s 28) and a version-currency row now exists because a newer release exists.

The bottom line Bump to v1.27.1 (released 2026-11-19, one patch) and retire the workaround queue in the same act: the hand-rolled transcriptMatchLog (~40 lines), the !items-stretch class args ×3, the hand-rolled tr[role=link]:focus-visible CSS, the pinned nav id, and the CopyButton-in-fragment prohibition all dissolve. This is the adoption-map watchlist’s “next release” — it shipped yesterday.

Prior reports this supersedes (newer + narrower wins): the 2026-10-24 deep-dive (91/100 at the v1.23.0 pin, 38 capabilities) and the fleet report docs/review/libs/templ-components.md (95/100, refreshed 2026-11-12 at v1.27.0). Superseded claims: (a) “v1.27.0 is the latest release” — v1.27.1 tagged 2026-11-19; (b) “the retirement wave rides the next release” — it now has a concrete version. The fleet’s 95 is not contradicted: it scored 26.5 of 28 applicable rows with version currency treated as current; this audit re-counts at a wider denominator (38) and adds the now-stale currency row.

Scrollback “?q=” match path hand-rolls the render loop — v1.27.1’s ScrollbackLine ID/Class retires it

internal/web/detail.templ:419-460 (transcriptMatchLog) · chosen over display.Scrollback because the pin’s ScrollbackLine has no id/class hook (#51)

The plain transcript path uses display.Scrollback correctly (AriaLabel, Stagger:false — detail.templ:258-262). The search-match view re-rolls the loop by hand to give each turn an anchor id and a visible <mark>. v1.27.1 adds ScrollbackLine.ID and .Class with default rendering byte-identical — exactly the hook this hand-roll waits for (adoption map row, 2026-11-12 re-audit: “pin’s struct still lacks the fields (verified in module cache)”).

Recommendation On the v1.27.1 bump, delete transcriptMatchLog and feed Scrollback per-line IDs (fmt.Sprintf("turn-%d", i)) plus a match class; keep the golden as the parity pin.

Partially used · hand-rolled a11y CSS

Clickable-row focus ring is hand-rolled CSS; v1.27.1 builds it in — and removes the ARIA-invalid role=“link”

internal/web/static/app.css:124 (tr[role="link"]:focus-visible) · #49 closed 2026-11-07, rides v1.27.1

The pin renders role="link" on <tr> (forbidden by ARIA in HTML) and draws no focus ring; pbx-lens patches both locally. v1.27.1 deletes the role, keeps tabindex + Enter/Space activation, and ships the focus-visible outline itself. The local CSS rule and its assumptions retire with the bump; the row-href goldens re-pin.

Partially used · pinned id + guard test

SimpleNav id is pinned to keep renders byte-identical — v1.27.1 makes library ids deterministic

internal/web/calls.templ:44-46 (props.ID pin) · internal/web/nav_id_test.go (guard) · #55 closed 2026-11-07, rides v1.27.1

The pin’s utils.EnsureID mints a random mobile-menu id per render, which would defeat the ETag revalidation the HTTP stack leans on, so pbx-lens pins the id and guards it with a test. v1.27.1 derives <id>-mobile-menu deterministically from content — the pinned-id workaround and its guard can be evaluated for retirement (keep the golden; the pinned id may still be desirable for readability, now without being load-bearing).

Partially used · a rule, not code, today

CopyButton is barred from htmx-swapped fragments by policy — v1.27.1 lifts the bar

internal/web/detail.templ:85, 99 (full-page CopyButtons only) · #63 closed 2026-11-07, rides v1.27.1

The pin’s per-render singleton script never fires in innerHTML-swapped content, so the adoption map bans CopyButton inside swapped fragments. pbx-lens currently has no fragment-mounted copy button, so nothing is broken — the finding is an unlock: v1.27.1’s CopyButtonScript(nonce) page-level mount plus NoScript prop make fragment placement legal. Revisit if a polled region ever wants a copy affordance.

Partially used · fixed-size attrs

Sparkline stays fixed-pixel in fluid cards — v1.27.1’s Responsive mode fills the card

internal/web/dashboard.templ (Sparkline ×2) · #60 fix rides v1.27.1

The dashboard’s two Sparklines render at fixed size inside fluid cards. v1.27.1 adds Responsive (viewBox + w-full h-auto, crisp stroke via vector-effect), ZeroAware/ShowZeroLine for signed series. Volume/trend series are all-positive today, so Responsive is the relevant adoption; ShowZeroLine matters only if a delta series lands.

Partially used · copy precision

ListNote synthesizes count sentences that fit filters, not keyset truncation — v1.27.1 accepts a caller-written Message

internal/web/calls.templ:127 (ListNoteCount variant on the keyset list)

The calls list is keyset-truncated (“latest N”), but ListNote’s variants synthesize search-flavored advice (“Narrow your search”) that is false on a searchless list. v1.27.1 adds ListNoteProps.Message: the shared shell stays, the sentence becomes the caller’s (“Showing the latest N”). Small copy win on the bump.

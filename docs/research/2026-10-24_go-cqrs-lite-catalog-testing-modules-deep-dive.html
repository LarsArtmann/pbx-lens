00Summary

This audit covers three go-cqrs-lite families from the consumer side: the catalog/v4 documentation kit (builder, schema reflection, seven exporters, docserver), the testing stack (systemscenario v4.2.x, scenario/v4, testutil/v4, systemtest, eventtest), and the benchmarking stack (benchkit, cqrs-bench, metaengine/bench). It is the first deep dive on this dependency for pbx-lens; the only earlier research report (2026-10-12 http-stack adoption audit) covers the appkit UI trio and does not overlap.

The verdict splits cleanly down the middle. The catalog core is used superbly — the typed builder, reflection-derived schemas, the flow/channel/external-system federation modeling, and BOTH export trees (render + governance lint) are wired end-to-end into the eventcatalog-hub federation. The testing stack is the mirror image: pbx-lens hand-rolls, in one test file, exactly the job systemscenario ships — and none of the four testing modules is imported anywhere. The benchmarking stack is correctly unused: benchkit's factories are the v1 stack.Bundle that ADR-0123 removes in v5, and pbx-lens's four own go test -bench benchmarks already own the app-level lane that benchkit's own decision matrix assigns to that tool.

The bottom line The catalog story needs no rescue — it is the reference adoption in the fleet. The one structural gap is testing: internal/app/app_test.go:32-76 hand-builds a projection-host harness with a 20 ms poll loop and manual close/reboot choreography that systemscenario replaces with System(t, ctx, domain, deploy), deterministic ThenQuery polling, and depth specs for exactly the invariants pbx-lens sells (idempotent re-ingest, tombstone retirement, optimistic concurrency). Ride the 2026-10-24 pin wave first (one sweep, eight modules), then adopt the harness.

◆What's already excellent

Six of the twelve applicable capabilities are fully leveraged — and they are the load-bearing ones. The final two entries are not scored rows but earn their place by avoidance: the right benchmarking lane, and two footguns never stumbled into. These build the baseline the findings section improves on.

+
Typed catalog builder with reflection-derived schemas Every command and event is declared through the generic catalog.Command[T]/catalog.Event[T] surface, so message schemas derive from the domain structs and can never drift; the test pins that schemas are non-nil (internal/calls/catalog.go:24-86, catalog_test.go:105-107).
+

+
Full federation modeling Domains, user-of-record, read-only data stores with access modes, the webhook channel, and a seven-step call lifecycle flow with an external Telnyx actor — the hub's visualiser edges all resolve (internal/calls/catalog.go:88-236).
+
Producer/consumer graph derivation rides for free Because every event carries catalog.Sends, Catalog.DeriveProducersConsumers (which the EventCatalog exporter runs automatically) enriches the union with correct producer edges — zero extra work (go-cqrs-lite catalog/coeffects.go:12-35).
+
The bare stream-key contract is honored Projection keys go through calls.RecordKey = StreamID.Get(), matching projectionadapter v4.6.x's bare EventWithID.ID — the exact bug class go-cqrs-lite spent the 2026-10-17/23 waves eradicating (AGENTS.md, docs/gotchas.md).
+
Right benchmarking lane, correctly chosen Four app-owned Go benchmarks cover the real hot paths — concurrent poll, 10k export stream, 10k list, ETag hash cost (cmd/pbx-lens/serve_test.go:777, internal/web/export_consumer_test.go:145, internal/web/perf_test.go:88,148). benchkit's own matrix assigns exactly this lane to go test -bench.
+
Two footguns avoided, not stumbled into benchkit was not adopted despite the tempting name: its factories return the v1 stack.Bundle that v5 deletes (benchkit/README.md:8-13), and its workloads are library-owned synthetic types, not pluggable domain folds. Likewise systemtest stays untouched — its README says plainly it is "not a consumer import target" (systemtest/README.md:27-29).

01Findings

Seven findings, ordered by impact. Five carry a Missed Opportunity grade — four unscored-otherwise rows plus the release-wave currency finding (F2) — and two are partially-used notes. Zero anti-patterns: nothing in pbx-lens uses these modules against their grain.

Missed Opportunity · High impact

systemscenario unused — app_test.go hand-rolls its exact job

internal/app/app_test.go:32-138 · the only test file that boots the system

systemscenario (ADR-0153, systemscenario/v4.2.1) boots the SAME DomainConfig/DeploymentConfig the production binary uses and drives Given/When/Then chains with a frozen ManualClock — its stated property is that "harness tests cannot drift from production wiring; there is nothing to re-declare" (systemscenario/README.md, doc.go:14-16). pbx-lens instead hand-builds the harness in app_test.go: startProjections (lines 32-52) manually goroutines, cancels, and joins the projection host; awaitView (lines 54-76) polls metaengine.NewReader.Get in a 20 ms sleep loop with a blind 5 s deadline; the replay test (lines 117-138) manually closes, re-boots, and re-wires a second system. That is four hand-rolled responsibilities the library owns — and the poll loop reports only "did not converge", while ThenQuery reports the LAST probe outcome plus the last query error, distinguishing a stalled projection from wrong data (README "Timeout honesty").

The depth specs systemscenario v4.2.0 added map one-to-one onto pbx-lens's selling points: the idempotency spec (same command twice → event exactly once, redelivery a success no-op) is the content-hash re-ingest contract; ThenQueryEventuallyFails is the retention-tombstone story (a row that vanishes once the projection catches up); the OCC spec pins event.ErrVersionConflict through the Conflict family; DelayedDriver adds journal-latency chaos; SubscribeSSE asserts the browser wire path. A full scenario costs ~1.2-1.8 ms and ~9 MB (BenchmarkScenarioBoot, README "Cost of a scenario") — hundreds of scenarios stay in seconds. 

func TestCallLifecycle(t *testing.T) {
    ctx := context.Background()
    sc := systemscenario.System(t, ctx, domainConfig(), systemscenario.SQLite(t))

    sc.Given().Command(mustRecord(sampleObservation())).
        When(sameObservationAgain).   // content-hash replay
        ThenNoEvents().               // idempotent re-ingest
        ThenQuery(viewQuery(sc, ctx), expectedCallView)
}
Recommendation Add go get github.com/larsartmann/go-cqrs-lite/systemscenario/v4 (test-only import; rides the already-approved go-cqrs-lite family) and port app_test.go's three helpers onto it. Keep the SQLite-leg replay test — systemscenario.SQLite(t) is file-backed under t.TempDir() precisely so reopen-style assertions stay honest. Caveat: the module is marked Experimental (rides system's status, systemscenario/README.md "Status") — acceptable for tests, revisit at v5.

Missed Opportunity · Medium impact

catalog.Query unused — the read surface is absent from the hub

internal/calls/catalog.go:32-85 · declares 3 commands + 4 events, 0 queries

The builder supports catalog.Query[T](id) as a first-class message kind (catalog/README.md:98), and validateService lint-checks queries alongside commands and events (catalog/validate.go:117-122). pbx-lens's catalog declares the write-side vocabulary (record, enrich, retire) and the event stream, but none of its read queries — search, dashboard aggregates, the detail join — even though those are real reads over the read model (five metaengine.NewReader[CallView] scan sites in internal/web/queries.go, plus the metaengine.Query[callLookup, CallView] at internal/calls/projection.go:94). The hub union therefore documents half the service: a consumer sees what pbx-lens records but not what it answers. Since the commands are equally internal (this is a read-only lens with no inter-service callers), the inconsistency is one of completeness, not of architecture.

Recommendation Declare the aggregate's query vocabulary the same way: catalog.Query[SearchCallsQuery](catalog.MessageID("call.search"), …) etc. in BuildCatalog, keeping id parity with the query names in internal/web/queries.go.
Missed Opportunity · Low-medium impact

scenario/v4 decider DSL unused — decide variants asserted by hand

internal/calls/commands_test.go, domain_test.go · plain stdlib asserts

scenario/v4.4.3 is the functional-core tier: pure Given/When/Then over a decider with zero infrastructure — scenario.Given[Cmd,State](t, fold, init, events…), order-sensitive Then(types…), ThenError, ThenState, plus GivenProjection folds (scenario/README.md). pbx-lens tests its decide functions (Record/Enrich/Retire, supersede paths, the tombstone) with hand-written arrange-act-assert blocks per case. The DSL's value here is the vacuous guard (a scenario that never asserts fails) and refold-from-scratch isolation between assertions — both eliminate real test-smell classes in growing decide-variant suites. The richer event-corrected/supersede matrix is the natural first target.

Recommendation If systemscenario (F1) is adopted, adopt scenario/v4 in the same sweep for the decider-pure loops — it is that module's stated fast-path companion ("use scenario for fast decider-pure unit loops", systemscenario/README.md).
Partially Used · Low impact

WithSkipBootstrapFiles not passed — the render export re-emits hub-owned files

internal/cli/catalog.go:15-30 · the CLI has no skip-bootstrap switch

eventcatalog.WithSkipBootstrapFiles() (catalog/eventcatalog/options.go:7-21) exists exactly for per-service exports into a federation hub: the hub keeps its OWN eventcatalog.config.js/package.json, and sources re-emitting them create first-wins merge hazards. The fleet norm is skip-at-source — the mesh-demo source passes -skip-bootstrap in the hub's own job script (eventcatalog-hub/work/source-jobs.sh:24,29). pbx-lens's export cannot pass the option at all: RenderCatalog only threads plain. No live defect — verified in the hub's merge.py:7-9,877-889, bootstrap files are NEVER copied and a test asserts the leak cannot happen — but pbx-lens deviates from the fleet norm and relies on the hub's defense.

Recommendation Add a -skip-bootstrap flag (default on for hub exports) to catalogCmd that appends eventcatalog.WithSkipBootstrapFiles() to the exporter options in RenderCatalog.
Partially Used · Low impact

Catalog.Validate() unused — the test hand-rolls its duplicate-ID check

internal/calls/catalog_test.go:113-119 vs catalog/validate.go:25-74

The library ships (*Catalog).Validate() []Violation covering empty titles/versions, empty service IDs, message ID-or-name rules, duplicate message IDs across the whole catalog, and operation path/method consistency. The pbx-lens test re-implements one slice of that — the sorted-ids duplicate scan (catalog_test.go:113-119) — by hand, while the rest of the test asserts domain-owned facts (directions, owners, reads-from/writes-to edges, flow step count) that Validate deliberately does not cover. The hand-rolled half is pure duplication; the domain half is exactly right. 

// after the structural asserts:
if viols := cat.Validate(); len(viols) > 0 {
    t.Fatalf("catalog invalid: %v", viols)
}
Recommendation Replace lines 113-119 with the cat.Validate() call above; keep every domain-specific assert as-is. Also fixes the gocognit>25 warning on testService by shrinking it.
Missed Opportunity · Low impact · blocked on F2

catalog/architecture reference unexported (needs the v4.10.0 bump)

not used anywhere · capability ships in catalog v4.10.0

catalog/architecture renders the catalog as ONE self-contained .html file — sidebar, per-resource sections, Ctrl/Cmd-K search, light/dark, zero dependencies beyond stdlib, no Node toolchain (catalog/architecture/doc.go:1-23); ADR-0160 selections cut redacted slices via WithInclude/WithExclude, and docserver streams the same bytes at /docs/architecture. For pbx-lens this would put a attachable, email-able architecture reference one flag away — useful for audits and the planned golvie story. Honest weight: low. The federation hub already renders the union for browsers; this adds a self-contained artifact, not a capability the hub lacks. 

exp := architecture.NewExporter(architecture.WithTitle("PBX-Lens"))
_ = exp.ExportFile(calls.BuildCatalog(), "docs/architecture.html")
Recommendation After the F2 pin bump, add an -architecture switch to the catalog command writing the single file next to the eventcatalog tree.

04What the target state looks like

If opportunities 1-4 land, the app-level test suite reads as behavior specs over the real composition root — no goroutine choreography, no sleep loops, and the suite's fixtures are compiled from the same DomainConfig the binary boots: 

// one-time: lift the DomainConfig literal out of app.New into an
// exported helper so tests and the binary share it verbatim
func TestRecordIsIdempotentByContentHash(t *testing.T) {
    sc := systemscenario.System(t, context.Background(),
        app.DomainConfig(), systemscenario.SQLite(t))

    sc.Given().Command(mustRecord(sampleObservation())).
        When(mustRecord(sampleObservation())).  // same snapshot, re-ingested
        ThenNoEvents().                         // replay writes nothing
        ThenQuery(viewQuery(sc, ctx), expectedView)  // poll, honest timeout report
}

func TestRetireTombstonesTheView(t *testing.T) {
    sc := systemscenario.System(t, context.Background(), app.DomainConfig(), systemscenario.Memory())

    sc.Given().Command(mustRecord(sampleObservation())).
        When(retireCmd("retention:age")).
        Then("call.retired").
        ThenQueryEventuallyFails(viewQuery(sc, ctx))  // row vanishes when projection catches up
}
This is the target The harness deletes ~45 lines of lifecycle plumbing (startProjections, awaitView, the manual reboot), converts the 20 ms poll into the library's honest-timeout assertion, and makes each pbx-lens invariant a named, readable spec. The catalog side of the house is already at this standard — nothing to change there beyond opportunities 3-5.

Execution errata, 2026-10-25. The wave + testing + catalog plan ran: eight pins bumped to the 2026-10-24 tail wave; F1 closed — internal/app tests now boot through systemscenario over app.DomainConfig() / app.DeploymentConfig(dsn) (hand-rolled harness deleted), plus OCC/chaos/property-oracle depth, the scenario/v4 decide matrix, and a payload-hash golden. Two corrections to this report: (1) F2's "layout-stamp drift WARN covers call_views" was wrong — the stamp only covers collections registered with a layout plan (filter/sort fields or columnarLayout opt-in), and call_views has none, so there was never a stamped plan to drift; the WARN mechanism itself was proven live on a scratch collection. (2) F2's metaengine "silent drift exposure" therefore overstated; the wave's real payoffs are the architecture exporter, currency, and the sticky-stream-key + typed-decoder fixes. Suite-cost receipt: the systemscenario suite (13 tests incl. property oracle x N seeds) runs in ~2.0 s wall on the dev machine (two consecutive runs 1981/1973 ms), vs the deleted harness's 20 ms-poll design.

## PII export coverage matrix (R3)

What each `?pii` mode does to every field an export carries. The response's
`X-PII-Mode` header names the mode that produced the payload.

| Field                                                 | `pii=` plain (default) | `pii=hash`                        |
| ----------------------------------------------------- | ---------------------- | --------------------------------- |
| from_number                                           | raw as stored          | `sha256:<16 hex>` or `[redacted]` |
| to_number                                             | raw as stored          | `sha256:<16 hex>` or `[redacted]` |
| transcript (JSONL)                                    | raw text               | **raw text — NOT scrubbed**       |
| transcript_excerpt                                    | raw text (CSV + JSONL) | **raw text — NOT scrubbed**       |
| insight_summary                                       | raw text               | **raw text — NOT scrubbed**       |
| MOS, cost, duration, direction, kind, ids, timestamps | as stored              | as stored                         |

**Disclosure:** `pii=hash` bounds participant IDENTITY only. Free text
(transcripts, excerpts, insight summaries) can contain spoken numbers or
names and leaves the server raw in every mode. This is the documented
owner doctrine (2026-10-12, R21): the index stores raw by design (real
CDRs carry garbled parties), and the export gate is the PII boundary.
If a hash-mode export must be free-text-free too, that is a new scrub
feature — ask, do not assume the mode covers it.
